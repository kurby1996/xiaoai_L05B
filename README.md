# 小爱音箱 L05B 接入大模型

基于 [yihong0618/xiaogpt](https://github.com/yihong0618/xiaogpt) 的 Windows 本地部署，支持 DeepSeek 官方及硅基流动的 OpenAI 兼容接口。

## 已验证的功能

- 小米账号登录、短信验证码验证、选择小爱音箱 Play（L05B）。
- 读取音箱语音提问，将问题发送给配置的大模型。
- 使用 `use_command: true` 调用音箱原生语音播报，无需刷机。
- 修复本机遇到的 `-127 / client withdraw`：设备请求使用与登录相同的客户端标识。修改后实机播报成功，用户确认听到测试语音。
- 遇到带 `wait_second` 的 `-127` 响应，按服务器要求等待，最多重试一次。

2026-10-31 验证：15 项离线测试通过。仅验证了本次使用的 L05B 和账号环境，不保证所有型号或固件兼容。当前未启用联网搜索，天气等实时信息请使用小爱原生能力。

## 安装

安装 Python 3.12（上游要求 >=3.12、<3.15）和 Git，然后在 PowerShell 中执行：

```powershell
git clone https://github.com/kurby1996/xiaoai_L05B.git
cd xiaoai_L05B
python -m venv xiaogpt/.venv
./xiaogpt/.venv/Scripts/python.exe -m pip install -e ./xiaogpt -r requirements-printer.txt
```

## 使用

按顺序双击仓库根目录中的脚本：

1. **1-配置账号和模型.cmd**：输入绑定音箱的小米账号和密码；选择 DeepSeek 官方或硅基流动，填写对应平台的 API Key 和模型名。DeepSeek 的地址和模型已有预设，回车保留。
2. **2-登录并选择音箱.cmd**：按提示输入短信验证码（不是手机号），再选择列表中的 L05B 序号。
3. **3-启动小爱AI.cmd**：保持窗口运行，唤醒“小爱同学”后，以“请”或“帮我”开头提问，例如“请讲一个简短的笑话”。Ctrl+C 停止。

首次配置会从 `config.local.example.json` 生成本机的 `config.local.json`。`--use_command` 已由启动脚本自动传入，不需要对音箱说，也不需要手动输入。

电脑和程序需要持续运行。小米云端轮询可能有延迟，也可能先听到部分原生回答。默认使用单轮、非流式回答，不保证免唤醒连续对话。切换模型平台后需填写该平台自己的 Key。

## 本机敏感文件

`config.local.json` 明文保存本机填写的账号、密码和模型 Key，`state/.mi.token` 保存小米登录凭证。两者均被 Git 忽略；不要上传、分享或粘贴到 Issue。仓库只包含空凭证示例。

## 语音打印取件码（喵喵机 P1/P1B）

已结合本机 `F:\AI\喵喵机上位机` 的打印协议和已验证的蓝牙发送策略实现原生打印，不要求打开打印台网页。打印设置从该项目 `config.json` 只读加载；不修改该项目，也不写入取件码。

1. 打印机开机、有纸，电脑开启蓝牙。手机 App 和打印台网页先断开该打印机，避免争用连接。
2. 在本机配置中设置 `printer_enabled: true`；`printer_project` 指向打印台目录（用于读取字号、数字间距、留白、发送速度、尾部走纸设置）。目录不存在时使用内置排版默认值。
3. 重启小爱 AI，唤醒“小爱同学”后说：“打印1234”，默认打印取件码，无需“帮我”或“取件码”。原指令“帮我打印取件码 8888”仍支持。程序直接解析并发送打印数据，不把号码交给模型改写。普通问题仍交给大模型。

支持阿拉伯数字、逐位中文数字（例如“零零八八”）、横杠分段（例如“八杠三零二一”）；不支持“八千八百八十八”等数值读法或一次打印多份，识别不明确时会要求重新说。前导零会保留。

连接时自动发现唯一的 Paperang；附近有多台时，请在本机配置 `printer_address` 指定蓝牙地址。发送完成只表示打印数据已发送，仍需检查实际出纸；同一条语音事件去重，失败不自动重印。重复主动下达一条新指令会再打印一份。

2026-10-31 本机验证：20 项离线测试通过；完整指令处理器实机试打“8888”完成，用户确认正常出纸、文字完整。重启后仍需由用户实际说一次语音指令，完成唤醒到打印的端到端验证。

来源与限制：复用打印台的 P1/P1B UUID、384 点位图、CRC 种子、20 字节 BLE 分片、快速/稳定档及 56 单位/mm 走纸约定；文字由 Pillow 使用本机微软雅黑粗体渲染。蓝牙能力依赖 Windows 和具体打印机；网页若已经占用连接，需要先断开。

## 漏答与接收稳定性

已修正上游流程中“回答/打印时暂停轮询、每次只处理最新一条、队列容量只有1”的漏指令窗口。现在保持约每秒一次的轮询，读取最近20条记录，按时间排队并去重；队列容量64，满时不提前确认未入队的记录。程序启动前的历史记录不会重放，避免重启后重复打印。

轮询异常会记录错误类型后继续运行；登录刷新后同步语音查询凭证并重建播报客户端；暂停原生回答失败不会中止处理，播报状态确认额外等待最多15秒。模型返回空答案时会给出明确的语音提示。

普通模型问答仍以“请/帮我”触发，打印可直接说“打印1234”。未触发的语音会在窗口中说明原因。新指令排队执行，不代表能立即打断当前回答。设备未识别语音、网络中断时间过长或云端未提供记录时，仍无法保证接收。

2026-10-31：29项离线回归通过。只读实测语音接口3次均返回HTTP 200、业务码0及20条记录，单次请求约0.06–0.16秒；这是当时的接口测量，完整语音体验需重启后继续实测。`diagnose_voice.py` 可只读检查接口状态、条数和延迟，不显示语音内容，也不触发打印。
